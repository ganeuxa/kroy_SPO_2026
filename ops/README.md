# Резервная копия QA

`sh ops/backup-qa.sh` создаёт согласованную копию на локальном QA-стенде:
останавливает записи backend и процесс SeaweedFS, сохраняет pg_dump и полный
том media_test, проверяет читаемость архивов, записывает SHA-256 и коммит.
В finally-подобном trap сервисы запускаются снова, в том числе при ошибке.

Копии: backups/<UTC timestamp>. Каталог содержит персональные данные,
не коммитится; права новых файлов ограничены umask 077. Файл COMPLETE появляется
только после успешного завершения всех шагов. Копия не включает .env — его
ответственный хранит отдельно. Копирование требует окна обслуживания.

Для другого стенда необходимо явно адаптировать имя проекта и env-файл.
Не запускайте две копии одновременно. Автоматическое расписание не включено:
оно должно учитывать окно обслуживания и место хранения резервных копий.

Восстановление полного набора: проверить sha256sum -c SHA256SUMS, развернуть
отдельный compose-проект с теми же версиями Postgres и SeaweedFS, восстановить
БД через pg_restore --exit-on-error и распаковать media.tar.gz в пустой media-том
при остановленном storage. Затем запустить storage/backend, проверить API,
доступность фото и счётчики. Не распаковывать архив поверх работающего хранилища.
Перед переключением реального стенда провести проверку на отдельном проекте.

Проверка копии без изменения исходного стенда:

```bash
python3 ops/verify-backup.py backups/<UTC timestamp>
```

Скрипт проверяет SHA-256, восстанавливает БД в одноразовый PostgreSQL без сети,
распаковывает медиа и удаляет контейнер в finally. Это не запуск всего магазина
из копии; для такой проверки нужен отдельный полный compose-проект.
