## 14.10.2026. Где разворачиваем тестовое окружение (№7)

**Решение.** Тестовое окружение разворачиваем через Docker Compose на ноутбуке участника,
который не писал код развёртывания. Публичный хостинг и ВМ пока не используем.

**Почему.** Задание №7 разрешает локальную машину или контейнер. Запуск на чужой машине
сразу проверяет NFR-07 (запуск одной командой по README). HTTPS не нужен,
потому что доступ не публичный (NFR-10 относится к публичному доступу).

**Участники:** Иващенко А., Макеенков М.

## 14.10.2026. MinIO переносим на этап III

**Решение.** На этапе II не подключаем MinIO. В интерфейсе вместо фото товаров
показываем заглушки. Таблица `product_images` и поле `storage_key` остаются как есть.

**Почему.** Загрузка фото нужна админке (FR-13), а админка по плану относится к этапу III.
Без MinIO в окружении на один сервис меньше: развёртывание в №7 проще, а неделя
на этап II остаётся реальной.

**Участники:** Иващенко А., Макеенков М., Зайнуллин Я.

## 14.10.2026. Сценарий для работы №6

**Решение.** Сквозной сценарий этапа II: регистрация и вход, затем добавление товара
в корзину (FR-01, FR-02, FR-07). Оформление заказа (FR-08) делаем, если останется время,
иначе переносим на этап III.

**Почему.** В сценарии есть формы, запись в БД и ошибки ввода (занятый email,
короткий пароль, нехватка остатка), поэтому на нём удобно показать проверку
корректного и ошибочного ввода (№6, п.4). Каталог (FR-03…FR-06) уже работает
после №5, корзина опирается на него и на вход.

**Участники:** вся команда

## 14.10.2026. Порты окружения разработки настраиваются через .env

**Решение.** Порты БД, сервера и фронта на машине разработчика задаются
переменными `DB_HOST_PORT`, `BACKEND_HOST_PORT`, `FRONTEND_HOST_PORT`.
Наружу порты открыты только на 127.0.0.1.

**Почему.** У участников могут работать другие проекты на 5432, 8000 и 5173.
Привязка к 127.0.0.1 не даёт открыть БД в локальную сеть.

**Участники:** Иващенко А.

## 14.10.2026. Роль kroy_app входит по паролю из переменной окружения

**Решение.** Роль `kroy_app` создаётся с `LOGIN`, пароль берётся из `DB_PASSWORD` в `.env`.
Добавлены права по умолчанию (`ALTER DEFAULT PRIVILEGES`) для таблиц из будущих миграций.

**Почему.** В отчёте №4 роль была `NOLOGIN`: приложение не смогло бы подключиться.
Без прав по умолчанию у приложения не было бы доступа к новым таблицам после миграций.

**Участники:** Иващенко А., Есина В.
