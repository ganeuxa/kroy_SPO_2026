# Этап III. REST API

Автор: Макеенков М. (архитектор). Полное описание контрактов: [`api/openapi.yaml`](api/openapi.yaml), OpenAPI 3.1, проходит проверку `openapi-spec-validator`.
Открыть в редакторе: https://editor.swagger.io → File → Import file. После реализации тот же контракт будет в Swagger самого сервера: `/api/docs`.

Как устроены файлы: `api/openapi_current.json` — то, что уже реализовано (выгрузка из кода), `api/stage3-paths.yaml` — новые методы, `api/build_openapi.py` собирает из них `openapi.yaml`. Правки контракта вносятся в `stage3-paths.yaml`.

## 1. Общие правила (не меняются с этапа II)

| Что | Как |
|---|---|
| Префикс | все методы под `/api`, фронт ходит на относительный путь, Nginx проксирует |
| Вход | `Authorization: Bearer <токен>` из `/api/auth/login` |
| Ошибки | `{"detail": "Понятный текст на русском"}`; ошибки валидации 422 — формат FastAPI (`detail` списком) |
| Деньги | строка с двумя знаками: `"1290.00"` |
| Даты | ISO 8601 с часовым поясом: `"2026-11-05T14:03:00+03:00"` |
| Списки | `{"items": [...], "total": 42, "limit": 20, "offset": 0}` |
| Чужие данные | чужой заказ, чужая позиция корзины → **404**, а не 403: по ответу нельзя понять, существует ли запись |
| Админка | все `/api/admin/*`: без токена **401**, с токеном покупателя **403** «Недостаточно прав» (FR-16, NFR-04). Проверка одна, в зависимости `require_admin`, и висит на всём роутере, а не на каждом методе отдельно |
| Повтор запроса | `Idempotency-Key: <UUID>` у оформления заказа (необязателен) и оплаты (обязателен): повтор с тем же ключом возвращает тот же результат с кодом 200 и дубля не создаёт |

## 2. Коды ответов

| Код | Когда |
|---|---|
| 200 | успешно; повтор идемпотентного запроса |
| 201 | создано: заказ, платёж, товар, вариант, фото, корректировка остатка |
| 204 | удалено, тела нет (фото) |
| 401 | нет токена, токен истёк или пользователь заблокирован |
| 403 | не администратор на `/api/admin/*` |
| 404 | нет такой записи или она чужая |
| 409 | нарушает текущее состояние: нет остатка, пустая корзина, недопустимый переход статуса, заказ уже оплачен или истёк, дубль SKU |
| 413 / 415 | фото больше 5 МБ / не JPEG, PNG, WebP |
| 422 | неверный формат данных: тип, длина, диапазон, обязательное поле, адрес и способ доставки не сочетаются |
| 503 | БД или хранилище фото недоступны |

## 4. Изменения в уже работающих методах

Только добавления, старые поля остаются: фронт этапа II не сломается.

| Метод | Что добавляется |
|---|---|
| `GET /api/products` | `items[].image_url` — готовая ссылка на первое фото (`/media/...`) |
| `GET /api/products/{id}` | `image_urls` — ссылки на все фото по порядку; скрытые варианты (`is_active = false`) не возвращаются |
| `GET /api/cart` | `items[].image_url`; позиция со скрытым вариантом остаётся видна, но оформить её нельзя (409 при оформлении) |
| `POST /api/cart` | скрытый вариант — 404, как скрытый товар |

## 5. Примеры

**Оформление заказа (самовывоз)**

```http
POST /api/orders
Authorization: Bearer eyJ...
Idempotency-Key: 6f1c2b7e-3d4a-4b8e-9f0a-1c2d3e4f5a6b

{"delivery_method": "pickup", "pickup_point_id": 1, "contact_phone": "+79001112233"}
```

```json
201 Created
{
  "id": 5, "status": "new", "total_amount": "2580.00", "items_count": 2,
  "delivery_method": "pickup", "delivery_address": null,
  "pickup_point": {"id": 1, "name": "Пункт выдачи", "address": "Москва, Вернадского, 78", "hours": null},
  "contact_phone": "+79001112233", "comment": null, "cancel_reason": null,
  "created_at": "2026-11-05T14:03:00+03:00", "expires_at": "2026-11-05T14:18:00+03:00",
  "items": [{"variant_id": 1, "product_id": 1, "name": "Футболка базовая", "size": "M", "color": "белый",
             "sku": "TSH-B-M-WHT", "image_url": null, "quantity": 2, "price": "1290.00", "line_total": "2580.00"}],
  "payments": [],
  "history": [{"from_status": null, "to_status": "new", "changed_by": "customer", "comment": null,
               "created_at": "2026-11-05T14:03:00+03:00"}]
}
```

Ошибки: пустая корзина — `409 {"detail": "Корзина пуста"}`; товар кончился — `409 {"detail": "Недостаточно товара «Футболка базовая» (M, белый): в наличии 0 шт."}`; самовывоз с адресом — 422.

**Оплата**

```http
POST /api/orders/5/payments
Authorization: Bearer eyJ...
Idempotency-Key: 0d5e3c4b-2a1f-4e6d-8c7b-9a0f1e2d3c4b
```

```json
201 Created
{"id": 7, "order_id": 5, "status": "pending", "amount": "2580.00",
 "confirmation_url": "/pay/test/0b9f5c1e-8a2d-4f3b-9c7e-2d1a4b6c8e0f",
 "failure_reason": null, "created_at": "2026-11-05T14:04:10+03:00", "paid_at": null}
```

Фронт открывает `confirmation_url` — страницу тестового платёжного сервиса. Там кнопки «Оплатить» и «Отклонить», они вызывают `POST /api/test-provider/payments/{id}` с `{"result": "succeeded"}` или `{"result": "failed", "failure_reason": "Недостаточно средств"}`. Затем фронт возвращает покупателя к заказу и опрашивает `GET /api/payments/7`.

**Смена статуса админом**

```http
POST /api/admin/orders/5/status
{"status": "delivered"}
```

```json
409 {"detail": "Нельзя перевести заказ из статуса paid в delivered"}
```
